# Desktop WebView Stop dependency qualification

NativeCmpKit currently resolves `org.openjfx` 21.0.13 for Desktop. `Worker.cancel()` can reach `CANCELLED` while the HTTP peer still waits. `HTTP2Loader.fwkCancel()` sets a flag used to suppress callbacks. A request waiting for response headers has no body subscriber to observe the flag. The tested source change also cancels the `HttpClient` response future. [Issue #64](https://github.com/NativeCmpKit/NativeCmpKit/issues/64) · [Earlier verification decision](../decisions/0013-private-javafx-cancellation-candidate.md)

## Full-source verification

The Linux x64, Linux ARM64, macOS x64, macOS ARM64 and Windows x64 profiles of the manual native verification workflow use the complete `jfx21u` 21.0.13.1+1 source tree and the previously tested cancellation patch. The lock binds the annotated tag object, commit, tree, original loader, patch, Gradle Wrapper configuration and every admitted external Ivy file. GitHub's OpenJDK tag and commit records report unsigned objects. The check ties the build to their immutable identities. The ICU data and source archive both match the Unicode release's SHA-512 manifest and are separately pinned by SHA-256. The ANTLR tool from ANTLR matches the Maven Central artifact byte for byte. The macOS and Windows profiles match CMake 3.31.12 to Kitware's release digests and checksum manifest. [Source lock](../../tests/dependency/javafx-http2-cancellation/source-sdk-lock.json) · [OpenJDK tag](https://github.com/openjdk/jfx21u/tree/21.0.13.1%2B1) · [ICU 77.1 release](https://github.com/unicode-org/icu/releases/tag/release-77-1) · [Kitware CMake release](https://github.com/Kitware/CMake/releases/tag/v3.31.12)

Each profile configures Gradle's local Ivy repository and enables compilation of native WebKit and Media. The artifact records the build command and exit code, source tree inventory, installed toolchain, SDK binary digests, ELF, Mach-O or PE headers, and cancellation bytecode. The four existing native cases run on the newly built SDK without module injection. They cover a pending response before headers, incomplete plain and gzip bodies, and an independent concurrent request. Each requires peer EOF before teardown and a successful recovery on the same engine. A separate fixture verifies navigation replacement, cancellation with stage detachment, and 16 repeated cancellations with real peer EOF and a bound on Unix file descriptors or Windows process handles. The job uploads evidence only. [Workflow](../../.github/workflows/build-native-libs.yml) · [Cancellation fixture](../../tests/dependency/javafx-http2-cancellation/JavaFxPublicCancellationProbe.java) · [Lifecycle fixture](../../tests/dependency/javafx-http2-cancellation/JavaFxCancellationLifecycleProbe.java)

The Windows route uses a pinned Cygwin 2.941 installer. Its SHA-512 matches the Cygwin checksum list and its detached signature verifies against the installation guide's fingerprint `56405CF6FCC81574682A5D561A698DE9E2E56300`. Cygwin verifies the signed package index and the workflow records the installed versions. For a repeatable production build, retain the exact signed package index and package bytes alongside the runner toolchain versions. The upstream Gradle build resolves three Lucene 7.7.3 JARs for its Ensemble example during configuration of the SDK build. The pinned Apache release files match Maven Central and its Google mirror byte for byte. GnuPG verified all three Apache signatures using the archived project keys and primary fingerprint `CFCE5FBB920C3C745CEEE084C38FF5EC3FCFDB3E`. The profile builds the SDK and checks that its runtime contains only JavaFX JARs. The official 21.0.13 WebKit binaries require glibc symbol versions up to 2.17 on Linux x64 and 2.38 on Linux ARM64. Both macOS WebKit binaries declare macOS 11.0 as their minimum. Compare the corresponding rebuilt ABI metadata with these baselines before adoption. The stock 21.0.13 Linux archives carry eight `libavplugin` variants on each architecture. The source workflow now enables the upstream stub build so compatibility checks can require all eight output plugins. It pins four FFmpeg source archives whose signatures verified with `FCF986EA15E6E293A5644F10B4322F04D67658D8`, and three Libav archives whose full member contents matched their resolved Git commits. The historical stubs are build inputs with working codecs disabled. The SDK and staged JARs reject the stub libraries as runtime payloads. The source receipt records hashes for the GPL, Classpath and Assembly Exceptions, and the tracked runtime-module notices, including WebKit, ICU, GStreamer and libffi. [FFmpeg release signatures](https://ffmpeg.org/download.html#releases) · [Libav source](https://github.com/libav/libav/tags) · [OpenJFX media build](https://github.com/openjdk/jfx21u/blob/5497f2f46abff58bea405b310fb6c9670686709e/build.gradle#L3086-L3110)

After the SDK tests pass, the workflow stages the six original upstream modular publication JARs in a file-only verification repository. It matches their native bytes against the tested SDK and checks that the WebView loader class is identical. The independent consumer verifies its NativeCmpKit publication using both Gradle module metadata and POM-only resolution. In each mode it checks all six JavaFX classifier hashes across the four classpaths, existing WebView behavior, and transport closure on public Stop, replacement navigation and Compose disposal. This file-only test stage uses explicit JavaFX classifiers and leaves production Maven metadata, signing and dependency selection for the production qualification. [Independent consumer](../../tests/consumer/webview-desktop/README.md)

Production qualification additionally requires a repeatable image and toolchain, matching native corresponding sources and notices for every shipped classifier, dependency provenance and security review, and ABI and packaged consumer results on Linux x64, Linux ARM64, macOS x64, macOS ARM64 and Windows x64. Verify public Stop, repeated loads, navigation replacement and disposal while work is pending. Observe peer termination, resource accounting after repeated use, concurrent isolation, and performance against the ordinary dependency. The physical-device and publication gates are required independently.
